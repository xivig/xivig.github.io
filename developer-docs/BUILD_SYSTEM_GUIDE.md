# Build System & Workflow Guide

This guide explains how to use the development, build, and documentation tools provided in the Xivig Admin Template. These tools use a hybrid approach combining **Vite** for speed and **Gulp** for advanced asset optimization.

---

## 1. Development Workflow

### `npm run dev`
This is your primary command for daily development.
- **What it does:**
  1.  Cleans old build folders.
  2.  Starts the **Vite** development server.
  3.  Opens your default browser to `http://localhost:3000`.
- **Key Features:**
  - **HMR (Hot Module Replacement):** CSS and JS changes are reflected instantly without a full page reload.
  - **Handlebars Rendering:** Compiles your layout and partials on the fly.

---

## 2. Build & Optimization Workflows

### `npm run build`
Generates a production-ready version of the site in the `dist/` folder.
- **The Step-by-Step Process:**
  1.  **Clean:** Deletes the `dist/` and `exports/` folders.
  2.  **Vite Build:** Compiles all SCSS, JS, and HTML into the `dist/` folder.
  3.  **Image Optimization:** Compresses JPG/PNG images and creates WebP versions for better performance.
  4.  **HTML Refactoring:** Moves pages from `dist/app/pages/` to the root `dist/` folder to ensure clean URLs.
  5.  **Path Fixing:** Runs `replace-links.js` to ensure all asset paths work in any hosting environment.
  6.  **Vendor Copy:** Syncs critical `node_modules` (like jQuery, Bootstrap, FullCalendar) to the `dist/plugins/` folder.
  7.  **Minification:** Performs a final pass of JS and CSS minification on the compiled assets.
  8.  **Asset Export:** Prepares a final package for distribution.

### `npm run production`
The "Ultimate Build" command.
- **What it does:** Runs the entire `npm run build` process and immediately starts a local server to **preview** the final optimized results. Use this to verify your build before deploying.

---

## 3. Preview & Documentation

### `npm run preview`
Starts a local server to serve the content of the `dist/` folder.
- **Purpose:** Testing the production build exactly as it will appear when hosted.

### `npm run docs`
Starts a documentation server.
- **What it does:** Serves the content of the `developer-docs/` folder using a specialized Gulp task.
- **Purpose:** Reading the internal architecture guides (SCSS, JS, HTML) in a browser-friendly format.

## 5. Deployment to GitHub Pages

The `docs/` folder in this repository is specifically reserved for **GitHub Pages** deployment.

### How it works:
1.  **Automatic Sync:** Every time you run `npm run build` or `npm run production`, the final optimized files are copied from `dist/` to `docs/`.
2.  **.nojekyll:** The build process automatically includes a `.nojekyll` file in the `docs/` folder to ensure GitHub Pages doesn't ignore folders starting with underscores (like those generated by some build tools).

### Steps to Deploy:
1.  Run `npm run build`.
2.  Commit and push the changes in the `docs/` folder to your GitHub repository.
3.  On GitHub, go to **Settings > Pages**.
4.  Set the **Source** to "Deploy from a branch".
5.  Set the **Branch** to your main branch (e.g., `main` or `master`) and the **Folder** to `/docs`.
6.  Save, and your site will be live at `https://<username>.github.io/<repo-name>/`.

## 6. Troubleshooting the Build

-   **Missing Images:** Ensure your images are in `app/src/images/`. The build process looks specifically in that folder to optimize them.
-   **Link Errors:** If links are broken in `dist/`, check the `tasks/utils/replace-links.js` script. It handles the path normalization.
-   **Dependency Issues:** If a plugin isn't working in the build, ensure it is added to the `copyVendorPackages` task in `gulpfile.js`.
